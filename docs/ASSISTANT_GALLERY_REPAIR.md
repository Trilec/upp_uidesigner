# Gallery discovery and diagnostics repair

The native all-controls attempt exceeded the 524288-byte request budget during
discovery and its retry produced only a Grid insertion. An insertion proposal is
not a complete gallery or a standalone Designer document.

Configuration discovery now excludes theme fields unless include_theme=true is
requested. It retains authoring fields, constraints, defaults, child rules and
data contracts while omitting editor-only descriptive metadata. Canonical CLI
schemas and portable schema files remain complete. The 49 non-stock catalogue
entries occupy 292712 serialized tool-message bytes in the regression fixture.

Composition capacity is 256 nodes, still subject to the 65536-byte argument limit,
canonical validation and atomic Apply/Undo. The default execution budget is 12
rounds, 40 calls and 16384 output tokens; request bytes remain capped at 524288.
Wire output allows 8 MiB and each request has a 120-second overall timeout. The
provider can still enforce stricter limits. These are bounded allowances, not a
guarantee that every model can complete a complex design.

Retry prioritizes terminal failures and asks for the full requested composition
or an explicit missing-work report. It does not silently apply partial work.
Activity includes serialized tool-result sizes. Copy log exports complete card
text, statuses, activity and proposal JSON, including collapsed messages. Provider
credentials and configuration are not added to the log.

Verification: AppChatTests 28 checks, AssistantDesignerTests 255 checks, and a
successful Designer release build. The latter tests catalogue size, optional
style discovery, full folded log export and a 101-node atomic Apply/Undo. This is
not evidence that a live provider has produced the requested gallery. Native
window capture failed twice with 'foreground window did not report a process id';
the updated bin executable was launched but its Copy log layout remains visually
unverified. Retest the gallery through the native Assistant and inspect the
result before claiming full coverage.

Portable skills are generated by PackageSkills.py; both skill metadata checks and
all three existing JSON example preflights pass. Saved multi-profile selection,
direct OpenAI transport and embedded image/HTML attachments are separate pending
work; these capabilities are not enabled by installing the skills.
